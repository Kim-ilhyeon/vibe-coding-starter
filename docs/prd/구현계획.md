# 포트폴리오 구현 계획

[PRD](./PRD.md)의 필수 기능을 아래 다섯 태스크로 구현한다. 사용자가 태스크 번호를 지정하면 해당 태스크를 하나씩 진행한다.

## 1. 데이터 파일과 공통 틀

- **만들 것** — `src/data/profile.ts`에 소개, 숫자 요약, 활동·수상, 기술 숙련도, 프로젝트, 공개 링크를 타입과 함께 정의한다. 소개 문구와 기술 점수는 [기획서](./기획서.md), 프로젝트와 공개 링크는 [프로필](../profile.md), 활동·수상 이력은 PRD를 따른다. App Router 공통 레이아웃을 만들고 메인 섹션을 소개 → 숫자 요약 → 프로젝트 → 활동·수상 → 기술 스택 → 연락 순서로 배치한다.
- **사이트 제목** — 김일현 Portfolio
- **검색용 설명** — 김일현의 신입 백엔드 개발자 포트폴리오. 오류의 원인을 분석해 문제를 해결하고, 부족한 부분은 스스로 찾아 공부하며 채워 갑니다. 팀 프로젝트에서 맡은 역할과 직접 구현한 기능을 소개합니다.
- **PRD 완료 기준 5 중 메타데이터** — “브라우저 탭에 사이트 제목이 표시되고, 개발자 도구에서 사이트 설명 메타 태그를 확인할 수 있다.”

## 2. 첫 화면

- **만들 것** — 김일현의 이름, 기획서의 한 줄 소개, 프로필 사진을 표시한다. `public/이력서 사진.jpg`를 `/이력서 사진.jpg` 경로로 참조하고 `next/image`와 한글 대체 텍스트를 사용한다. 넓은 화면에서는 소개와 사진을 좌우로, 모바일에서는 세로로 배치한다. 바로 아래 어두운 배경의 숫자 요약 영역에 팀 프로젝트 2개, 개발 교육과정 2개 수료, 사용 기술 스택 19개를 표시한다.
- **PRD 완료 기준 1** — “메인을 열면 김일현의 이름, 한 줄 소개, 첨부한 프로필 사진이 보인다. 넓은 화면에서는 소개가 왼쪽, 사진이 오른쪽에 보이고, 그 아래 숫자 요약에 팀 프로젝트 2개, 개발 교육과정 2개 수료, 사용 기술 스택 19개가 표시된다.”

## 3. 소개·기술 스택

- **만들 것** — 활동 5건과 수상 2건을 각각 날짜 또는 시작일 순서로 표시한다. 수상에는 수상자와 내용을 포함한다. 기술 19개를 분야별로 묶고, 5점 만점의 자기평가 점수를 0.5점 단위의 숫자와 동일한 척도의 막대로 표시한다. Oracle DB는 프로젝트 외 실습으로 표시한다.
- **PRD 완료 기준 2** — “활동 5건과 수상 2건이 각각 날짜 또는 시작일 순서로 보인다. 기술 19개가 분야별로 표시되고, 5점 만점의 자기평가라는 안내가 보인다. Spring MVC는 5점으로 막대가 가득 차고 Spring Boot는 3.5점으로 전체 길이의 70%가 채워진다.”

## 4. 프로젝트 카드

- **만들 것** — 프로젝트 제목과 카드 목록 사이에 네 가지 필터를 배치하고 처음에는 전체를 표시한다. 모아와 쉽코딩은 모두 팀 프로젝트와 KH 정보교육원에 포함한다. 카드에는 이름, 한 줄 소개, 주요 역할을 표시하고 선택한 분류에 카드가 없으면 빈 목록을 안내한다. 두 프로젝트의 상세 페이지에 이름, 목적, 기간, 팀 규모, 사용 기술, 역할과 주요 구현 내용, 프로젝트별 GitHub 저장소 링크와 개인 블로그 링크를 표시한다.
- **PRD 완료 기준 3** — “프로젝트 목록 위에 전체, 팀 프로젝트, 개인 프로젝트, KH 정보교육원 필터가 보인다. 전체와 팀 프로젝트에서는 모아·쉽코딩 카드가 보이고, 개인 프로젝트에서는 빈 목록 안내가 표시된다. KH 정보교육원 필터에서는 해당 분류에 등록된 카드만 보이며, 등록된 카드가 없으면 빈 목록 안내가 표시된다. 모아 카드를 선택하면 `/project/moa`, 쉽코딩 카드를 선택하면 `/project/easycoding`이 열린다. 상세 페이지에서 목적, 기간, 팀 규모, 사용 기술, 본인의 역할과 구현 내용을 읽을 수 있고, GitHub와 블로그 링크는 각각 해당 저장소와 개인 블로그로 이동한다.”
- **확정된 분류 확인** — 전체, 팀 프로젝트, KH 정보교육원에서 모두 모아와 쉽코딩 카드 2개가 보이는지 확인한다.

## 5. 연락 링크와 모바일 화면 점검

- **만들 것** — 메인 하단의 어두운 연락 영역에 개인 GitHub, 개인 블로그, 공개용 개발 이메일 링크를 표시한다. 모바일 너비에서 메인과 프로젝트 상세 페이지 두 곳을 열어 가로 스크롤, 소개와 사진의 세로 배치, 링크 선택과 이동을 확인한다.
- **PRD 완료 기준 4** — “메인에서 개인 GitHub, 블로그, 공개용 개발 이메일 링크가 보인다. GitHub와 블로그 링크는 각 페이지를 열고, 이메일 링크를 선택하면 기기에 설정된 메일 앱에서 공개용 개발 이메일이 받는 사람에 입력된다.”
- **PRD 완료 기준 5 중 모바일** — “브라우저를 모바일 너비로 줄여도 메인과 상세 화면의 콘텐츠가 가로 스크롤 없이 보이고 링크를 선택할 수 있다.”

다크 모드, 사이트 내 블로그, 방명록, 다국어, 방문자 통계는 이번 구현 범위에서 제외한다. 각 태스크 구현 후 `pnpm lint`, `pnpm test`, `pnpm build`를 실행하고 각 명령의 출력을 기록한다.
